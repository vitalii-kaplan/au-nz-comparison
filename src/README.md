# Research Analysis Development Plan

This document translates `AU_NZ_visa_comparison_methods.md` into a reproducible research-module pipeline. Methods Sections 1--15 are implemented and tested, with the prerequisite Section 11 comparability gate executed before its dependent analyses and Sections 12--15 providing final reproducibility, output-inventory, interpretation-boundary, and pipeline controls.

## Scope and implementation rule

Each numbered section of the methods specification maps to one independently runnable and importable Python module under `src/`. Statistical modules may read only:

- verified tables under `data/prepared/`;
- machine-readable configuration and contracts committed to the project; and
- artifacts produced by an earlier analysis module in this plan.

They must not read `data/original/`, manually transcribed article values, or files generated outside the recorded pipeline. Shared calculation, validation, plotting, and provenance functions will also live under `src/`, while each numbered analysis module remains the public command-line entry point for its methods section. Modules will use importable names such as `analysis_03_descriptive.py` and support execution with `python3 -m src.analysis_03_descriptive`.

Preparation, extraction, harmonization, and general project utilities remain under `scripts/`; statistical research code does not belong there. Every analysis module will have a corresponding test module under `tests/`, with unit tests for calculations and boundary cases and integration tests for its declared input/output contract. Tests should run with Python's standard `unittest` discovery unless an additional test dependency is explicitly adopted; the same tests may also remain compatible with `pytest` collection.

The principal deliverables are CSV tables for the article Results section. Figures, JSON manifests, diagnostic text, and model objects are supporting artifacts. Article tables and prose will consume machine-generated outputs; values must not be copied manually into separate analysis code.

The audit confirms that each pooled table reconciles exactly to the sum of its four normalized annual tables by destination and country.

## Shared configuration and output conventions

All analysis modules read the shared configuration file `src/analysis_config.json`, which contains at least:

- analysis years: 2022--2025;
- destination labels and reference destination;
- random seed for bootstrap procedures;
- confidence level;
- denominator thresholds of 20 and 50 in each destination;
- sensitivity-analysis thresholds of 0, 20, 50, and 100 decisions in each destination;
- Benjamini--Hochberg FDR level;
- sparse-table decision rule;
- continuity-correction rule;
- bootstrap replicate count;
- figure formats and resolution; and
- software-specific model settings.

Every result CSV should use stable machine-readable column names, UTF-8 encoding, an explicit sort order, and enough denominator and population columns to interpret the result without consulting a figure. Every analysis module should also write a JSON run record containing input paths and SHA-256 hashes, output hashes, software versions, execution time, configuration values, row counts, exclusions, warnings, and validation status.

Planned result directories are:

```text
data/prepared/comparison/     Validated analysis tables shared by later scripts.
data/results/validation/      Contracts, overlap, missingness, and comparability audits.
data/results/descriptive/     Dataset summaries and distribution statistics.
data/results/paired/          Matched-country differences and paired tests.
data/results/concordance/     Pearson and Spearman results.
data/results/country_tests/   Complete country-specific effects and tests.
data/results/models/          Binomial models, diagnostics, and model contrasts.
data/results/composition/     Origin shares and concentration measures.
data/results/temporal/        Annual summaries and matched country-year results.
data/results/robustness/      Pre-specified sensitivity comparisons.
data/results/manifests/       Run manifests and final artifact inventory.
data/results/figures/         Reproducible analytical figures before article selection.
```

## Planned research modules by methods section

### 01 — Units, notation, and estimands

**Module:** `src/analysis_01_define_contract.py`
**Tests:** `tests/test_analysis_01_define_contract.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Convert the definitions in Methods Section 1 into a machine-readable contract used by all later modules. It will define the country, destination-country, and destination-country-year units; count and rate formulas; direction of differences (`AU - NZ`); decision-weighted, country-weighted, and country-year estimands; reference destination; study years; and interpretation scope.

**Inputs:** `src/analysis_config.json`, `data/schema.json`, and the two pooled normalized tables for contract verification.

**Primary artifacts:**

- `data/results/validation/analysis_contract.csv` — variable, unit, formula, weighting perspective, and permitted interpretation;
- `data/results/validation/input_registry.csv` — expected prepared input and role; and
- `data/results/manifests/01_analysis_contract.json`.

The module will fail if required fields or configured destination/year definitions disagree with the prepared-data contract.

### 02 — Data validation and derived tables

**Module:** `src/analysis_02_build_tables.py`
**Tests:** `tests/test_analysis_02_build_tables.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Validate pooled and annual prepared inputs and create the only analytical tables consumed downstream. Checks will cover schema and type conformance, key uniqueness, duplicate rows, non-negative integer counts, `approved + declined = total`, rate reconstruction, rates in `[0,1]`, year coverage, sorted keys, pooled-to-annual reconciliation, country overlap, destination-only origins, and small denominators.

**Inputs:** the Section 1 contract and all pooled and annual M49-based prepared tables.

**Primary artifacts:**

- `data/prepared/comparison/destination_country_2022-2025.csv` — long table with one row per destination-country;
- `data/prepared/comparison/matched_country_2022-2025.csv` — one row per common country with AU and NZ counts, rates, and `rate_difference_au_minus_nz`;
- `data/prepared/comparison/destination_country_year.csv` — one row per destination-country-year;
- `data/prepared/comparison/matched_country_year.csv` — one row per common country-year;
- `data/results/validation/data_validation_checks.csv` — check, scope, observed value, expected value, and pass/fail status;
- `data/results/validation/country_coverage.csv` — country presence by destination and year;
- `data/results/validation/small_denominators.csv`; and
- `data/results/validation/data_issues_and_exclusions.csv` — including zero unresolved issues as an explicit valid result.

No inferential module may run unless all blocking validations pass.

### 03 — Descriptive comparison

**Module:** `src/analysis_03_descriptive.py`
**Tests:** `tests/test_analysis_03_descriptive.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Describe scale, aggregate approval structure, country decision volumes, and country-rate distributions without significance testing. Aggregate rates are calculated from summed counts, never by averaging country rates. Log10 decision counts are derived only for summaries and figures where totals are positive.

**Inputs:** `destination_country_2022-2025.csv` and the validation outputs.

**Primary CSV artifacts:**

- `data/results/descriptive/dataset_summary_by_destination.csv` — represented countries, approvals, declines, decisions, and aggregate approval rate;
- `data/results/descriptive/country_level_distribution_statistics.csv` — n, min, Q1, median, Q3, max, mean, SD, and IQR for decisions and approval rates; and
- `data/results/descriptive/approval_rate_ecdf_points.csv` and `decision_volume_ecdf_points.csv` — exact plotting data.

**Figures:** approval-rate ECDF and histogram/density, log10 decision-volume ECDF or histogram, and an optional box/violin plot.

### 04 — Matched-country approval-rate comparison

**Module:** `src/analysis_04_matched_comparison.py`
**Tests:** `tests/test_analysis_04_matched_comparison.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Quantify the country-weighted distribution of paired AU-minus-NZ approval-rate differences and perform the two-sided Wilcoxon signed-rank test. The module reports zero-difference handling explicitly, calculates a conventional 95% CI for the mean, calculates a seeded bootstrap 95% CI for the median, and runs the paired t-test as sensitivity rather than as the primary test.

**Inputs:** `matched_country_2022-2025.csv` and configuration.

**Primary CSV artifacts:**

- `data/results/paired/matched_country_differences.csv` — complete country-level paired counts, rates, and differences;
- `data/results/paired/matched_difference_summary.csv` — n, mean, median, SD, IQR, range, CIs, and positive/negative/zero counts;
- `data/results/paired/paired_test_results.csv` — Wilcoxon and paired t-test statistics, sample size, p-value, alternatives, and zero policy; and
- `data/results/paired/median_bootstrap_distribution.csv` — all 10,000 seeded bootstrap median draws.

**Figure:** paired-difference distribution or ordered dot plot with a zero reference line.

### 06 — Country-specific differences

**Module:** `src/analysis_06_country_differences.py`
**Tests:** `tests/test_analysis_06_country_differences.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Calculate a complete 2-by-2 comparison for every matched country. It will report approval-rate difference as the primary effect, plus risk ratio and odds ratio where defined, with confidence intervals. The test-selection rule will use expected cell counts to choose an asymptotic two-proportion/chi-square test or Fisher's exact test. Any continuity correction will be recorded per row. Benjamini--Hochberg adjustment will be applied across the full country-test family.

**Inputs:** `matched_country_2022-2025.csv` and the analysis configuration.

**Primary CSV artifacts:**

- `data/results/country_tests/country_specific_effects_and_tests.csv` — all countries, denominators, rates, RD/RR/OR with CIs, expected counts, selected test, raw p-value, BH q-value, and warning flags;
- `data/results/country_tests/country_test_summary.csv` — counts by test type, FDR status, effect direction, and denominator band; and
- `data/results/country_tests/forest_plot_selection.csv` — complete and displayed-set flags with the pre-specified display rule.

**Figure:** forest plot of selected rate differences with 95% CIs. The complete numerical table remains the authoritative result.

### 07 — Binomial regression

**Module:** `src/analysis_07_binomial_regression.py`
**Tests:** `tests/test_analysis_07_binomial_regression.py`

**Status:** Implemented and tested on 27 September 2026.

**Purpose:** Fit count-based binomial models for destination association while controlling for country, and, when annual inputs pass comparability checks, country and year. The country-year model will use cluster-robust standard errors by origin country. The reference destination and coefficient direction will be fixed in configuration.

**Inputs:** `matched_country_2022-2025.csv`, `matched_country_year.csv`, comparability outputs from Sections 2 and 11, and configuration. The matched inputs implement the gate's rule that observations must exist in both destinations.

**Primary CSV artifacts:**

- `data/results/models/destination_probability_contrasts.csv` — model-based AU/NZ probabilities and percentage-point contrast with uncertainty;
- `data/results/models/model_fit_statistics.csv`;
- `data/results/models/model_diagnostics.csv` — convergence, separation, overdispersion, extreme fits, warnings, and covariance method; and
- `data/results/models/influential_observations.csv`.

Serialized fitted objects may be saved for reproducibility, but CSV coefficients and diagnostics remain mandatory. The script must fail visibly on non-convergence or unresolved separation rather than suppressing warnings.

### 08 — Applicant-origin composition

## Development sequence and acceptance criteria

Implementation should proceed in the same dependency order as the pipeline, with each analysis module and its matching test module accepted before work begins on its consumers. For each module:

1. define and document input and output schemas;
2. implement deterministic calculations and stable sorting;
3. add the mirrored `tests/test_analysis_*.py` module with focused tests for formulas, boundary cases, sparse/zero cells, deterministic output, and failure conditions;
4. run against the verified prepared inputs;
5. reconcile totals and row counts against upstream artifacts;
6. inspect warnings and statistical diagnostics;
7. confirm a second run produces identical deterministic artifacts, except recorded timestamps; and
8. update `process_log.json` only after the script and outputs have passed their stated validation.

No article Results prose should be drafted from a planned or partially validated output.
